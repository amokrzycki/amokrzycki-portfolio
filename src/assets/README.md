## Implementation evidence

The selected story follows shared product identity across languages, the transaction that captures an order, and the boundary between pending MFA and a full session. AuthExplanation replaces the MFA form capture; the crop and public original were retired because they did not explain the authentication boundary. No captures were added. General admin dashboards, user tables and settings pages were explored but omitted from the case study.

- **Storefront:** category selection, product search, sorting, quantities and basket controls work in the English interface. Filters use the URL; Redux Persist stores only the basket. `src/api/api.ts` and `src/store/store.ts` in the frontend establish locale-aware query keys and state persistence. Backend `src/services/product.service.ts` joins the requested translation with a Polish fallback and searches/sorts those localized names.
- **Staff catalogue:** the products, orders and users workspaces were accessible to the supplied administrator account. The product editor exposes both translations alongside shared stock and price. Saving the editor was exercised with synthetic data. Frontend `src/components/Admin/Products/AddProductForm.tsx` and backend `src/services/product.service.ts` implement this shared record.
- **Checkout and orders:** the English checkout accepted the synthetic account's addresses and created the captured order. The customer view showed the stored lines, delivery, status and invoice action. A downloaded PDF was verified as a PDF with English labels and the expected products and total. Backend `src/services/order.service.ts` stores addresses, lines and stock deductions transactionally, preserves the order locale and item names, then generates the invoice. Order confirmation templates also use the stored language; delivery through Mailgun was not verified as part of the local capture pass.
- **Account and authentication:** login, orders, address book, email/password forms and MFA settings were inspected. Email MFA was enabled for the disposable account, its pending screen was captured, and the Mailpit-delivered code completed login. TOTP and WebAuthn enrollment and verification are present in source; a physical authenticator was not exercised. Backend `src/auth/mfa.service.ts` separates pending tokens from sessions, expires login challenges after five minutes, limits failed attempts and consumes challenges transactionally.

This is a personal application without a commercial launch or payment gateway. Checkout still accepts client-supplied prices and checks stock without explicit row locks. Invoice generation follows the commit, and staff edits do not automatically regenerate the PDF. Several management endpoints need server-side role and ownership enforcement. Refresh sessions have no server-side revocation registry; throttling is per backend instance. The public technical disclosures reflect these limits without claiming production-scale security or measured improvements.
